    用量统计口径与数据来源

    数据从哪来（自动扫描与多工具发现）

    本地代理只转发加密流量，看不到模型与 Token，所以用量不从代理采集，而是每分钟经 SSH 只读扫描团队服务器上已安装的 AI 工具与会话日志（按文件偏移 / SQLite 游标增量读取，服务器上不落任何文件），结果保存在本机，保留 90 天。个人服务器不统计。

    • Codex：~/.codex/sessions，逐次调用取 token_usage_record（旧版本按 token_count 累计值差分）。
    • Claude / ReClaude：~/.claude/projects（含子 Agent），同一请求的多份记录取用量最大的一份。
    • Antigravity (agy)：~/.gemini/antigravity-cli/conversations/*.db 与 ~/.gemini/antigravity/conversations/*.db，只读解析 gen_metadata 与 steps 表。
    • Gemini CLI：~/.gemini/tmp/*/chats/session-*.jsonl。
    • ZCode / OpenCode：~/.zcode/cli/db/db.sqlite 与 ~/.local/share/opencode/opencode.db。
    • Cursor / 自定义 AI：~/.cursor/projects/*/agent-transcripts，以及自定义 JSONL 目录 ~/.config/cluster-workbench/usage-logs（或在服务器配置中指定 customUsageDirs）。

    口径

    • 四个基础量：普通输入、缓存写入、缓存读取、输出；总 Token = 四者之和。
    • 未命中输入 = 普通输入 + 缓存写入，即实际新增的输入量，全页同一算法。
    • 时间一律按北京时间（UTC+8）：按每次调用的时间归日，跨零点的会话拆到两天。失败调用计入调用次数，不计 Token。
    • 失败调用的错误原文：v2.51 起随扫描保存（单行、最多 300 字、远端与本机各脱敏一次，每台服务器总量上限 1 MiB），在会话详情里点「原文」查看；没有状态码的失败按原文归类，认不出的记为「其他」。更早的记录没有原文。
    • 「近期活跃」= 最近 5 分钟有新日志；「暂无新记录」= 今天有记录但最近 5 分钟没有。
    • 上下文 = 最近一次成功主线调用的输入合计 ÷ 窗口。Codex 与 Antigravity 窗口优先取日志记录，其余按模型名与观测值推断，标「估」。
    • 每轮耗时：Codex 取 task_started → task_complete，Claude 取 turn_duration，Antigravity / ZCode / Gemini CLI 取单轮步骤起止时间。
    • 日历里最早有数据之前的日期标为「未采集」。远端过期清理的日志历史保留在本机。

    不展示的

    • 首 Token 时间、流式中的实时 Token（日志不记录）、订阅额度（号池均衡分配）。

          🔑 集群 Root 一次性赋权操作指南
          
        检查中
        
      
          
      
          
        
          无需在工作台日常保存高风险的 root 私钥。只需用集群 root 账号给你的管理员账号（如 kai）执行一次以下最小权限赋权，即可永久解锁三项能力：
          
        
          
          
          1. 共享目录全权接管：将 /public/agent-hub 及其子目录属主设为你的管理员账号，无需每次敲命令即可直接清理任何人的闲置端口文件与占坑文件。
          
          
          2. 强踢卡死/僵尸隧道端口：在成员列表操作栏一键终止集群上卡死占着反向端口不放的 sshd 会话子进程。
          
          
          3. 未安装客户端成员无感兜底采集：即使某个组员没有打开工作台，也能通过受限只读辅助脚本（3 分钟缓存）自动统计其家目录占用与 ~/.codex / ~/.claude 调用量。
          
        
          
        
          
          
          
            操作步骤（仅需执行一次，30 秒完成）
            
          
          
          
          第 1 步：在终端以 root 身份登录集群（或在有 sudo 权限的终端执行 sudo -i）；
          
          
          第 2 步：点击右上角「一键复制赋权脚本」，粘贴到集群 root 终端回车执行（看到 ✅ 团队管理员 Root 赋权已完成！ 即可）；
          
          
          第 3 步：回到本弹窗点击下方「验证赋权并刷新状态」。
